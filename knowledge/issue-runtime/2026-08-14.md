## Cases

### CASE: retire-issues-via-event-append-not-code-change
status: auto
problem: Issues 48 (ACTIVE, stuck), 54 and 82 (PENDING, superseded by 104) needed to be moved out of the active backlog before a live drain, and 48 specifically needed to stop being ACTIVE because recovery's `_expected_commit` would reset the workspace to its stale pinned `base_commit`.
decision: Retired all three by appending legal `IssueEscalated`/`IssueActivated` events through the existing event log and replaying, rather than changing `ISSUE_TRANSITIONS` or writing an ad hoc state mutation in src/.
why: The retirement had to replay cleanly through the frozen `_issue_transition` legality check without touching the FROZEN architecture/transition table (CLAUDE.md: architecture changes require an ADR); using the log itself as the mutation channel needed no code change and no ADR.
tags: [event-sourcing, state-machine, retirement, recovery-hazard]

### CASE: pending-issues-need-activate-before-escalate
status: auto
problem: Issues 54 and 82 were PENDING, but the goal was to move them to NEEDS_HUMAN (a terminal state), and it wasn't obvious whether that could be done directly.
decision: Confirmed via full dump of `ISSUE_TRANSITIONS` that no `(PENDING, *)` key maps to a terminal state — the only legal PENDING transition is `(PENDING, ISSUE_ACTIVATED)→ACTIVE` — so the retire script issues `IssueActivated` then `IssueEscalated` for each PENDING issue instead of a single escalate event.
why: `_issue_transition` raises `TransitionError` for any `(state, EventType)` pair not in the table; a direct PENDING→NEEDS_HUMAN escalation would have failed replay.
tags: [event-sourcing, state-machine, transitions, replay-legality]

### CASE: edit-tool-not-get-content-set-content-for-issues-md
status: auto
problem: Needed to delete three issue blocks from StockPhotoAgent's Issues.md without corrupting its encoding.
decision: Used the Edit tool to delete the blocks rather than `Get-Content`/`Set-Content`, then verified zero U+FFFD replacement characters post-edit.
why: Explicitly instructed as "preserve UTF-8, no mojibake" — `Get-Content`/`Set-Content` round-tripping is a known corruption risk for non-ASCII content (em-dashes etc.) in PowerShell.
tags: [powershell, encoding, utf-8, git]

### CASE: retiring-active-48-eliminates-reset-hazard
status: auto
problem: Recovery's `check_dirty_workspace` resolves `_expected_commit` for an ACTIVE issue from `proj.issue_base_commit[iid]` when it has no execution yet; issue 48 was ACTIVE with `base_commit` pinned to the stale commit `0143486`, meaning any future recovery pass on 48 would `git reset --hard` the target repo back to that stale commit.
decision: Retiring 48 to NEEDS_HUMAN (via the event-append above) was treated as the fix for this hazard, not just backlog cleanup — because once 48 is no longer ACTIVE, `_active_issue(proj)` returns no id and `_expected_commit` falls through to `adapter.head_of(target_branch)` instead of 48's pinned base_commit.
why: Traced directly through `bindings.py`'s `_expected_commit`/`check_dirty_workspace` logic in an earlier investigation turn; confirmed empirically in the live drain (`Select-String` over drain output for "reset workspace to 0143486" returned zero matches).
tags: [recovery, git-reset, hazard, reconciler]
