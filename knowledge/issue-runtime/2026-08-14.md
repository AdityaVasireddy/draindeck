### CASE: gitignore-bare-dir-blocks-negation-use-wildcard
status: auto
problem: Added `scratch/` plus a negation `!scratch/events_prebackup_*.jsonl` to `.gitignore` to ignore scratch junk while keeping the real-log prebackup trackable; `git status --porcelain` showed the prebackup file had vanished from the untracked list — the negation was silently ineffective.
decision: Replaced the bare `scratch/` line with `scratch/*` (keeping the negation line unchanged immediately after), which restored the prebackup file to the untracked/trackable list; verified with `git check-ignore -v` before and after.
why: Git will not descend into an already-ignored directory to evaluate a negation pattern on a file inside it — a bare directory pattern (`scratch/`) blocks re-inclusion of anything under it, while a wildcard pattern (`scratch/*`) still lets git walk into the directory per-entry so the negation can match. `git check-ignore -v` confirmed the file was matched by the `scratch/` line specifically, isolating the root cause before the fix was applied.
tags: [git, gitignore, negation-pattern, repo-hygiene]
