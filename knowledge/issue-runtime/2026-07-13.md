### CASE: production-no-blanket-reset-before-executing
status: distilled

decision: confirmed NO by grepping `loop.py` and `git_adapter.py` — production's `_execute` uses `checkout_branch(create_from=base)`, which refuses outright on a dirty tree; its `reset_hard` calls only occur on reject/escalate paths after a terminal outcome; `_validate` performs no reset of its own.
why: this settles that production genuinely depends on recovery check 3 healing the tree at a mid-VALIDATING crash — the harness worker's blanket reset does not model production, so equating the two would have been a fidelity gap.
tags: [production-fidelity, harness, git-adapter, reconciler]

#### JUDGMENT (distilled 2026-07-25)
Rejected alternative: assuming production resets the worktree before every attempt the same way the harness worker does, which would make the "joint coverage" claim accurate without further checking.
Tradeoff: assuming equivalence is free but risks hiding a real production dependency on the reconciler; grepping the actual call sites costs a few minutes but grounds the fidelity claim in code instead of assumption.
Tipping factor: `_execute`'s `checkout_branch` refuses outright on a dirty tree and `reset_hard` only fires on reject/escalate paths, so no blanket reset exists on the path the harness worker mimics — production genuinely depends on check 3.

#### JUDGMENT (distilled 2026-07-25)

Tipping factor: the transition table already forbids `(NEEDS_HUMAN, ISSUE_ESCALATED)`, so a real duplicate can never reach `verify()` — the only way to know the assertion fires was to bypass the guard that would otherwise mask it.

### CASE: config-ini-gate-must-run-without-real-config
status: distilled

decision: the gate must supply its own test-scoped config (a temp config generated from `config.ini.example` with a path/env override, or `CONFIG_FILE` stubbed pre-import) and must be green with the real `config.ini` absent.
why: user cited Issue 4 as prior evidence of this exact hidden-dependency failure mode.
tags: [testing, config, gate-design]

#### JUDGMENT (distilled 2026-07-25)
Rejected alternative: letting the gate rely on a real, present `config.ini` in the environment it runs in.
Tradeoff: relying on the real file is simpler to wire up but creates a hidden dependency on an untracked credential file, so the gate's pass/fail silently depends on environment state instead of the code under test.
Tipping factor: Issue 4 was cited as prior, concrete evidence of exactly this hidden-dependency failure mode recurring, making the test-scoped-config requirement non-negotiable.
