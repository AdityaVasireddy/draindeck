## Decisions & Rationale
- **`ValidationCfg.env: dict[str, str | None]` added to `src/runtime/config.py`** — a `None` value means "unset this key in the child," not "leave it inherited" and not "set it empty." Rationale (per ADR-23, doc 08 §5d, carried from session 14): `VIRTUAL_ENV=""` still tests `True` under `"VIRTUAL_ENV" in os.environ` while an unset var tests `False` — an additive-only overlay cannot express "absent," only "present with some value," so it cannot neutralize the specific vector behind the original bug. Verified this session that `extra="forbid"` (already on `_Frozen`) is still live — a typo'd sibling key and the same dict inserted one config level up (`project.env` instead of `project.validation.env`) are both rejected.
- **`Validator._child_env()` added to `src/runtime/validation/runner.py`, wired into `_run_once`'s `subprocess.run` via `env=`** — previously `subprocess.run` passed no `env=` argument at all (the actual defect ADR-23 addresses; the child silently inherited the full parent environment). Built as a single pass over the overlay, mutating a fresh `dict(os.environ)` base: `built.pop(key, None)` when the overlay value is `None`, else `built[key] = value`. The pop-from-**base** (not pop-from-overlay) detail is load-bearing — an early draft of this session's own reasoning got this backwards (see Outstanding Issues), and the fix was caught before being written into code, only in prose that a reviewer (the user) corrected.
- **Both `Validator(...)` call sites in `src/runtime/main.py` (baseline check, ~line 204/207, and the orchestrator's validator, ~line 227/230) now pass `env=cfg.project.validation.env` identically** — rationale: if baseline ran under a different (or no) overlay than the real per-issue validation, that would reintroduce a version of the exact shell-state divergence ADR-23 exists to close, just between two different runtime call sites instead of between two operator shells.
- **New test file `tests/unit/test_validation_env_adr23.py` (6 tests), following the existing `test_engine_adr22.py` idiom** — assert on the value `_child_env()` returns, never on `subprocess.run`'s call arguments (mirrors how `_hygienic_env()` is tested for ADR-22). The single most important test (`test_inherited_key_nulled_is_absent_from_child`) asserts **membership-absence** (`"VIRTUAL_ENV" not in built`), not a value comparison — a value-based assertion like `.get(...) is None` would have passed even under a broken pop-from-overlay implementation, so it wouldn't have caught the bug this test exists to catch.
- **No `config.yaml` change** — the schema field exists and `runner.py` reads it, but no config supplies a real overlay yet. Deliberate: adding `validation.env:` to `config.yaml` is out of scope until a live differential run actually needs a real overlay value, and doing it earlier would exercise the key with nothing meaningful to verify against.
- **The ADR-spec end-to-end differential (originally "step 6") was explicitly deferred, not attempted, not partially run** — see Deferred Work. This was a judgment call surfaced to the user mid-session (three converging structural blockers, not a single gap), and the user's explicit decision was to defer with all three blockers named rather than attempt a partial/simulated version of the check.
